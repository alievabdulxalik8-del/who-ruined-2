# Who Ruined 2.0

Разбор проигранного матча Dota 2 по Match ID: был ли один игрок, который провалил игру сильнее
остальных, или проиграли командой. Игрока сравниваем с другими игроками на том же герое и позиции.

Готовы этапы 2–4 плана: сервер-посредник собирает данные из OpenDota и Stratz,
проверяет режим, ждёт разбора матча, ловит ливеров/фидеров, определяет позиции,
считает балл вины каждого игрока и выносит вердикт. Страница (этап 5) — дальше.

## Сервер: Edge Function `dota-analyze`

Supabase-проект `hyjyfmgskcjijyyblvtg`, код в `supabase/functions/dota-analyze/index.ts`,
кеш — таблица `dota_cache` (`supabase/migrations/`). Вызов с anon-ключом проекта:

```
POST https://hyjyfmgskcjijyyblvtg.supabase.co/functions/v1/dota-analyze
{ "match": "8123456789" }                                  // или ссылка OpenDota / Dotabuff / Stratz
{ "match": "8123456789", "refresh": true }                 // пересчитать, минуя кеш
{ "player": "https://steamcommunity.com/profiles/7656…" }  // 10 последних игр для выбора
```

Ответ `status`:
- `parsing` — OpenDota или Stratz ещё разбирают матч; спросить снова через `retry_after_sec` (15 с).
  Ждём до 4 минут, потом считаем по тому, что есть (`sources.wait_timed_out`). Разбор без Stratz через час
  пересчитывается: функция ещё раз спрашивает Stratz.
- `rejected` — не оцениваем: `reason` = `mode` (Ability Draft, 1v1 и т.п.), `lobby` (лобби, боты),
  `short` (короче 15 минут), `surrender` (досрочная сдача без ливера); текст в `message`.
- `ready` — `stage: "leaver"` (ливер или фидер среди проигравших — вердикт без формулы) либо
  `stage: "verdict"`: `verdict.kind` = `main` («Главная причина — X»), `two` («Ошиблись X и Y») или
  `team` («Проиграли командой», подробности в `team_report`), плюс `confidence` и из чего она сложилась.

Главное в `ready`: `match` (длительность, режим, `turbo`, проигравшая сторона), `players` (позиция 1–5 и её
источник, пометка «позиция неточная» с причинами, IMP Stratz, ливер с минутой, фид), `lanes` (итоги линий
для проигравших), `flags` (`turbo`, `not_parsed`, `no_stratz`, `positions_from_opendota`, `position_uncertain`),
`positions_agree` (доля позиций Stratz, совпавших с признаками OpenDota), `links`.

Каждый игрок (все 10, победители — для сравнения) получает `score` 0–100 (100 — худший) и
`score_parts`: Герой, Линия, Смерти, Драки, Роль — с цифрами, из которых посчитана каждая часть.

## Формула (score.ts)

Части и веса по позициям — как в плане. Отличия от плана, найденные на реальных матчах:

- **Смерти:** «дорогие» смерти (поздние, перед потерей здания/Рошана) сдвигают балл, а не умножают его:
  `100 − процентиль смертей + 20 × (средний вес − 1)`. С умножением у половины проигравших было 100.
- **Поправки по позициям (`POS_OFFSET`):** каждая часть выровнена так, чтобы её среднее у pos 1–5
  было одинаковым. Без этого мид всегда «плох» по урону зданиям (−20), керри — по доле урона к доле золота.
- **Калибровка (`POS_CALIB`):** у коров итог гуляет вдвое сильнее, чем у саппортов (σ 20 против 13),
  и без калибровки виновником почти всегда выходили pos 1–2. Итог = «насколько хуже типичного игрока
  своей позиции», переведённое в общую шкалу.
- **Порог «главного виновника»:** разрыв 12 вместо 15 (после калибровки шкала у́же). Остальные пороги — из плана.

## Подбор (14.10.2026)

53 матча Ranked All Pick трёхдневной давности (OpenDota `parsedMatches`), 530 игроков. Размеченных
вручную матчей («мы сами знаем, кто проиграл игру») пока нет, поэтому независимой проверкой служил
IMP Stratz — собственная оценка игры, которую формула не использует:

| Вердикт | Доля матчей | Совпадение с худшим IMP в команде | Случайно было бы |
|---|---|---|---|
| Главный виновник | 19% | 7 из 7 | 20% |
| Двое | 42% | 9 из 12 (один из двух — худший) | 40% |
| Командой | 40% | — | — |

Виновники распределены по всем позициям (до калибровки — только pos 1–2).
Турбо в подборе не участвовал (отдельные нормы OpenDota есть, поправки взяты общие).

Следующий шаг подбора — 30–50 матчей с ручной разметкой (свои игры) и ответы кнопки «Не согласен».

## Токен Stratz

Не хранится в коде. Функция берёт секрет `STRATZ_TOKEN` из Edge Functions, а если его нет —
из Supabase Vault (`stratz_token`, читается только через `dota_stratz_token()` под service_role).
